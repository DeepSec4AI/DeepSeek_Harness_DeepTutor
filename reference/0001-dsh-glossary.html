0001 · dsh 核心术语表

速查用 · 术语拿不准先查这里 · 与官方 docs/glossary.zh.md 对照

项目与框架

dsh / DeepSeek Harness
DeepSeek AI 开源的 agent harness（智能体运行时框架），提供 CLI 与 Web UI，MIT 协议。README.zh.md
agent harness（智能体运行时）
驱动 LLM agent 循环的程序：组装提示词 → 调模型 → 执行工具调用 → 把结果喂回模型。区别于「评测框架」。
Cordis
dsh 底层的插件框架（vendored，源码在 vendor/cordis/src/，约 2700 行）。插件向共享上下文贡献服务、类型化事件和可逆副作用。docs/cordis-primer.zh.md
插件（plugin）
向 Cordis 树贡献内容的基本单元，可以是一个函数，也可以是 Service 子类。dsh 的每一部分都是插件，包括 agent loop 本身。
Context / ctx
所有插件共享的容器（一个 Proxy 对象），服务按稳定键认领位置，如 ctx.tools、ctx.llm。vendor/cordis/src/context.ts
Service（服务）
挂在 ctx 键上的具名能力基类：class ToolRuntime extends Service。随插件卸载自动注销。
Fiber
插件生命周期单元：跟踪状态、收集副作用、卸载时按逆序回滚全部注册。vendor/cordis/src/fiber.ts
inject
插件声明依赖的方式：static inject = ['systemPrompt']，框架保证被依赖服务就绪后才启动。

会话与事件

Session（会话）
只追加（append-only）的 SessionEvent 日志。UI、fork、恢复、遥测、回放全部从它派生。packages/core/session/src/index.ts:425
事件溯源（event sourcing）
不直接存「当前状态」，只存「发生过的事件」；需要状态时从事件流投影。dsh 用 deriveMessages() 从日志投影模型历史。
模型可见即已记录
dsh 的核心不变量：抵达模型请求的一切都必须能从日志重建，有运行时断言检查。新增模型可见输入 ⇒ 必须新增会话事件。docs/architecture.zh.md
三大事件域
① 会话事件（持久事实，写入日志）；② Agent 事件 agent/*（观察/拦截进行中的工作）；③ 能力事件（向 seam 附加策略与适配器）。
waterfall（瀑布式分发）
事件总线的一种模式：监听器收到 (...args, next)，必须调用 next() 才继续向下游传递，可拦截可改写。另有 emit / parallel / serial 三种模式。docs/cordis-primer.zh.md

Agent 与循环

Agent（接口）
活跃智能体的契约：send / followup / steer / inject / cancel / whenIdle 等。纯接口，无继承树；ReactLoopAgent 是默认实现。packages/core/agent/src/runtime-types.ts:64
轮次（turn）与步骤（step）
一个步骤 = 一次模型请求 + 它调用的工具；一个轮次 = 零个或多个步骤，从领取首条输入前开启，到不再欠任何工作时关闭。
ReactLoopAgent
默认驱动器（496 行），实现 turn/step 状态机。packages/core/agent-loop/src/agent.ts:64
Phase
驱动器的三态：idle（空闲）｜maintenance（维护中）｜running（跑轮次）。用可辨识联合定义。agent.ts:38
Inbox
驱动器的双通道输入队列：next-turn（开启新轮次的消息）与 next-step（注入当前轮次的上下文/转向）。
steering（转向）
Agent 运行中插入新指令、改变其行为方向的机制；与 followup（排队下轮）、inject（注入上下文）相区分。

工具与模型

工具（Tool）
面向模型的能力，由 ToolDefinition 描述（名字、JSON schema、执行函数），注册到 ctx.tools。
ToolRuntime
ctx.tools 背后的服务：作用域化注册表 + 执行流水线（tools/pre-execute → execute → post-execute）。packages/core/tools/src/index.ts:787
SystemPrompt
ctx.systemPrompt：有序的提示词分片注册表，每次请求前组装成系统提示词（含工具 schema）。
LlmAdapter（模型适配器）
模型提供方的接缝：抽象类，唯一必须实现的方法是 stream(options) 返回异步流。已有 llm-deepseek、llm-pi-ai 等实现。packages/llm/llm/src/index.ts:180
能力 seam（接缝）
一项可替换能力的完整设计，三角色：Service Definition（声明接口）/ Provider（实现）/ Consumer（使用，通常是工具）。docs/capability-seams.zh.md

组合与配置

插件行（row / 条目）
插件清单里的一行：{ id: 名字, name: npm 包名, config: 配置 }。id 是各层 patch 定位它的锚点。最终插件树 = 行的列表。
组合包（bundle）
厂商预制并随 npm 包分发的「一摞插件行」。本质是一个普通 npm 包，其 package.json 里 dsh.bundle.patch 指向自己的 cordis.patch.yml。出厂有 dsh-base（地基：模型、工具、持久化、沙箱…约 70 行）、dsh-web-app（加浏览器界面）、dsh-headless（加一次性运行器）。packages/bundle/base/cordis.patch.yml
profile
~/.dsh/profiles/<名字>/ 下的一个目录：内含 package.json（dsh.profile.bundles 按序列出要叠的组合包 + 树外插件依赖）和自己的 cordis.patch.yml。web、headless 是随发行版交付的模板，装到你机器上后可随意改。packages/boot/app-boot/src/profile.ts:5
patch（cordis.patch.yml）
对插件清单的编辑指令，只有两种动词：- insert:（插入新行）与 - id: xxx（按 id 整体替换该行的 config，不做字段合并，同 id 后写的赢）。层级顺序：各 bundle → profile 的 patch → home 级 patch → --patch 命令行叠加。packages/bundle/web-app/cordis.patch.yml
Harness home
dsh 的用户数据根目录：~/.dsh（Windows：C:\Users\<你>\.dsh）。profiles、凭据、会话数据都住这里。packages/boot/app-boot/src/index.ts
agent preset
让某个会话/agent 拥有不同能力集合的预组装配置（见 apps/cli/config/agent-presets/）。
scope（作用域）
把注册项限定到单个 agent 的原语：铸造带标签的子 Context，事件沿 WeakMap 父链向上流动。packages/core/scope/src/index.ts
dispose（注销）
每项注册都返回精确的注销函数；插件卸载时按逆序执行。dsh 的铁律：注册与注销必须严格嵌套。
subagent（子智能体）
由主 agent 派生的下级 agent；提供方接口统一，实现从「新建子 agent」到「把一轮委派给另一个产品（如 Claude Code）」不等。
